셸 스크립트 배포와 fastlane 배포

같은 학원 앱 하나를 배포할 때, 각 단계를 사람이 하는지 자동으로 진행되는지를 왼쪽·오른쪽 레인으로 나눴습니다. 셸 스크립트만 쓰던 시기는 단계가 두 레인을 계속 오가고, fastlane 도입 후에는 사람이 명령을 실행한 뒤로 전부 자동 레인에서 진행됩니다.

사람이 하는 단계7→2기존 학원 업데이트 기준

도입 전에는 빌드와 업로드는 스크립트로 한 번에 했지만, 서명 확인과 업로드 이후의 웹 작업은 사람이 했습니다. 도입 후에는 설정 파일 작성과 명령 실행 두 번이면 끝납니다.

무엇이 달라졌나

서명이 특정 Mac에서 풀려났다

예전엔 Xcode 자동 서명이라 인증서가 깔린 내 Mac에서만 빌드가 됐습니다. match가 Git 저장소에서 인증서와 프로파일을 받아 오니 다른 Mac이나 GitHub Actions에서도 같은 결과가 나옵니다.

업로드 뒤의 웹 작업이 사라졌다

altool은 .ipa를 올리는 것까지만 했습니다. 처리 대기, 스토어 정보 입력, 심사 제출, Play Console 출시는 웹에서 손으로 했는데, 이제 deliver와 supply가 처리합니다.

기존 빌드 스크립트는 그대로 살렸다

학원별 아이콘과 번들 ID를 바꾸는 build.sh는 버리지 않고 fastlane이 호출하게 했습니다. 잘 돌던 부분은 두고, 사람이 하던 앞뒤 단계만 자동화했습니다.

실제 저장소의 스크립트와 Fastfile을 바탕으로 정리했습니다. 번들 ID와 학원 이름은 생략했고 인증 키 값은 넣지 않았습니다. App Store Connect의 새 앱 생성은 Apple API가 허용하지 않아 도입 후에도 웹에서 한 번 합니다.
